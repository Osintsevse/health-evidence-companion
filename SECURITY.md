# Security and privacy reports

Do not publish credentials, actual medical information, private links or sensitive logs in an issue, PR or test fixture.

If a public copy contains sensitive material, contact the maintainer through a private GitHub security report **if that feature has been enabled**. Otherwise use a public report stating only that a private reporting route is needed, without the data, identifiers or disclosure location. The project does not currently advertise a verified private email channel.

The maintainer should stop affected releases, revoke exposed credentials, remove affected current material and separately assess Git history, artifacts, releases, caches and copies. Deleting a current file alone is insufficient. Notify the appropriate owner through an authorized private route.

CI includes heuristic checks and blank-template checks. They cannot prove that all personal data, medical errors or security vulnerabilities are absent; human review remains necessary. Runtime external documents are untrusted evidence and must not override skill instructions.
