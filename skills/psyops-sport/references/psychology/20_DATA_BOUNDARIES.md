# Separation of general, personal and shared data
Version 2.0 · design storage and reading rules

| Block | Acceptable Content | Must exclude |
|---|---|---|
| General | Sources, methods, risks, exercises, fictitious examples, blank templates | User names and history, personal preferences, real episodes, personal journal addresses |
| Personal | Information provided by a person, his goals, history, brief summary; hypotheses separately | Statements about another person as established fact; other people's secret notes |
| Joint | Agreed participants and rules; their explicitly presented positions; approved general records | Automatic copy of the personal archive of one participant, hidden instructions in his favor |

## Don't confuse properties
Separation into folders is the organization and rule of assistant access, and not separate accounts, encryption or an insurmountable limit on the model’s memory. Permissions on a parent folder can extend to content. You can only transfer a clean general block, not the entire parent folder.

The shared folder should start with clean files: editing a private file "to an anonymous view" may leave details in the version history. In a generalization of a real case, a combination of nameless details is sometimes recognizable. Prefer new synthetic examples. Do not use current personal stories as public test scripts without specific permission.

## Record structure
For each significant entry, indicate the date of the report, source, status, and possibility of correction. Statuses: reported by participant; agreed upon by both; disputed; working hypothesis; deprecated/fixed. The absence of an objection does not change the entry to “confirmed”.

Store minimally sufficient summaries, not default transcripts. An agreed-upon permanent record setting can be in effect without re-authorization for each summary. Exceptions like “don’t save”, “this is not for general conversation” should be done according to the context. Do not store additional third-party identifiers and medical details unless necessary.

There is no promise of everlasting memory or recording between messages. If saving is not available, state this explicitly; do not create the appearance of continuity. Correct the factual error in the current profile and mark the previous entry as erroneous so that it does not return as a fact.

## Transfer between blocks
A general methodological finding can be added to the general block after removing the personal context and checking the source. Transfer a personal episode into a joint context only purposefully; permission to disclose does not make one person's version the general truth. Consent to a joint journal does not authorize its publication or forwarding.
